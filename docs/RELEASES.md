# Betas and stable releases

The intended distribution channel is GitHub Releases on the project repository.

- **Beta builds:** generated by GitHub Actions from the development branch or a manually selected commit. Each beta should be marked pre-release and include its source commit, build manifest, checksums, limitations, and exact tested device variants.
- **Stable releases:** generated from a version tag such as `v0.1.0`, only after build validation and hardware smoke testing. The release must identify the tested device model and the tester's boot result.
- **Artifacts:** one release ZIP containing the required boot image, embedded storage image, optional device-tree overlay only if required, install instructions/scripts, build manifest, and checksums. Do not include unrelated firmware or `vbmeta` by default.
- **Reproducibility:** pin Batocera, ARMDeck, kernel, and postmarketOS initramfs revisions. Store the revision list and build parameters in the artifact. Never describe a CI-only build as hardware-tested.

GitHub Actions supports manual `workflow_dispatch`, tag-based workflows, and persisted workflow artifacts; see <https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows> and <https://docs.github.com/en/actions/concepts/workflows-and-actions/workflow-artifacts>.

## Current status

The current prototype has separate baseline build, integrated handoff build, and assembly workflows. The assembly workflow uploads an inspection bundle only. It is not a release, is not hardware-tested, and must not be flashed. GitHub Release publishing remains disabled until the integrated build has succeeded, the generated boot image has been inspected, and IN2017 testing is completed.
